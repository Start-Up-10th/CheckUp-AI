# datagsm-webhook — 학생 정보 동기화 계획

## 담당자·API

- 담당자: 강민우
- `POST /api/v1/webhook`

## 구현

- `X-DataGSM-Signature` 검증 후 학생 정보 변경 이벤트를 수신한다.
- `event`, `timestamp`, `old`, `new`를 검증하고 중복 이벤트를 멱등 처리한다.
- 학생 이름·학년·반·번호·호실 변경을 내부 데이터와 동기화한다.
- 확인된 전학·퇴사·졸업 대상의 벡터·캐시·백업 삭제를 연계한다.
- 누락·일시 장애만으로 학생 삭제나 벡터 삭제를 실행하지 않는다.
- 정상 수신은 명세의 `204 No Content`, 서명 실패는 `401`로 처리한다.

## 계약 보완

- [ ] DataGSM의 실제 event 값과 서명 알고리즘을 확인한다.
- [ ] `old/new` 내부 전체 필드와 학생 식별자 타입을 확인한다.
- [ ] 재전송 idempotency key와 이벤트 timestamp 순서 규칙을 정한다.
- [ ] 삭제 대상이 DB·Redis·기기 캐시·백업 복원에서 재출현하지 않는지 운영 계약을 정한다.

## 기준·검증

- 요구사항: `REQ-AUTH-002`, `REQ-FACE-003`, `REQ-OPS-004`
- 수용 시나리오: `ACC-AUTH-002`, `ACC-FACE-003`, `ACC-OPS-004`
- 잘못된 서명·중복 이벤트·오래된 이벤트·부분 데이터·DataGSM 장애를 구분한다.
- 동기화 실패가 현재 학생 권한이나 출석 기록을 잘못 삭제하지 않는지 확인한다.
