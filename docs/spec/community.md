# 봉사·공지·알림

### REQ-COM-001 — 봉사자 명단

관리자는 봉사자 명단에 학생을 추가·제거한다. 학생은 관리 API를 사용할 수 없다.
봉사자 관리에서 `+ 봉사자 추가`로 전체 학생 검색 화면에 이동한다.
검색 기준은 이름/학번이며 placeholder는 `이름 또는 학번으로 검색`이다.
행 좌측 이름·학번·호실, 우측은 미등록 `추가`(라임), 등록됨 `제외`(빨강) 버튼으로 표시한다.
추가 성공 후 명단에 반영하고 버튼을 제외로 바꾼다. 이미 등록된 학생은 중복 추가하지 않는다.
제외 시 `봉사자 명단에서 제외할까요?` 다이얼로그에 이름·학번·호실, 취소/제외 버튼을 표시한다.
제외는 명단 소속 제거이며 누적 횟수는 유지한다. 이는 원문 가정을 채택한 구현 기본값 DEC-010이다.
재추가가 누적 횟수를 중복 생성하거나 초기화하지 않는다.

| 결과 | 문구 |
| --- | --- |
| 추가 성공 | 봉사자 명단에 추가했습니다. |
| 중복 | 이미 명단에 등록된 학생입니다. |
| 추가 실패 | 명단 추가에 실패했습니다. 다시 시도해 주세요. |
| 제외 안내 | 적립된 봉사 횟수는 그대로 유지됩니다. |
| 제외 성공 | 명단에서 제외했습니다. |
| 제외 실패 | 명단 제외에 실패했습니다. 다시 시도해 주세요. |

근거: SRC-ADMIN-UI의 봉사 관련 항목, SRC-COMMUNITY.

### REQ-COM-002 — 봉사 횟수 적립

관리자 목록에 이름 / 최근 활동 / 봉사 횟수를 표시한다. 최근 활동 없으면 `-`, 횟수는 `0회`다.
각 학생의 횟수 배지 옆 `+` 클릭은 봉사 1회를 즉시 적립한다. 별도 확인 단계나 활동명 선택은 없다.
적립 날짜를 기록하며 활동명은 비운다. 최근 활동에는 날짜만 표시한다.
통신 재시도는 같은 클릭을 두 번 적립하지 않지만 사용자가 새로 누른 별도 클릭은 1회를 더 적립한다.
성공: `봉사 1회를 적립했습니다.` 실패: `봉사 적립에 실패했습니다. 다시 시도해 주세요.`
감소/취소 UI는 현재 범위에 없다. 전체 평균·총 적립 통계와 학생 이름 클릭 상세도 추가하지 않는다.

근거: SRC-ADMIN-UI `봉사 횟수 적립`, `학생 봉사 횟수 조회`, SRC-HANDOFF.

### REQ-COM-003 — 학생 봉사 조회

학생은 본인의 누적 봉사 횟수만 확인한다. 다른 학생 조회나 수정은 불가하다.
최신 사용자 확정의 `학생은 자기 봉사 횟수만 확인`이 과거 첨부의 활동별 내역 목록보다 우선한다.
봉사 횟수는 일일 출석 초기화 때 지우지 않는다.

근거: SRC-COMMUNITY, SRC-HANDOFF.

### REQ-COM-004 — 공지

사감·자치위원 모두 공지를 작성·수정·삭제할 수 있다. 학생은 공지 목록을 읽기만 한다.
공지 제목/내용·작성/수정 시각과 목록 표시는 웹/백엔드가 설계한다. 댓글·첨부·상단 고정·예약 발행은 추가하지 않는다.
새 공지 등록 알림은 `기숙사 공지 알림 수신`을 선택한 학생에게만 생성한다.
알림 미동의 학생도 공지 목록은 볼 수 있다. 선택 동의를 공지 열람 권한과 혼동하지 않는다.
공지 수정/삭제 때 별도 새 알림을 발송하는 기능은 정의되지 않았다.

근거: SRC-COMMUNITY의 사용자 직접 결정.

### REQ-COM-005 — 웹 내부 알림

남기는 유형은 출석 완료, 봉사 활동 등록, 기숙사 공지사항 등록 3개다.
얼굴 재등록 요청과 QR 만료 임박은 명시적으로 삭제됐다. 새로운 알림 유형을 만들지 않는다.
출석 완료 알림은 상태가 실제 성공 처리될 때 생성한다. 중복 인증은 중복 발송하지 않는다.
봉사 알림은 1회 적립 시 생성하는 구현 기본값을 사용한다. 단순 명단 추가와 구분한다(DEC-010).
공지 알림만 선택 동의에 연결한다. 서비스 범위는 웹 내부 알림이며 푸시는 포함하지 않는다.
모바일 홈 헤더 벨에 읽지 않은 알림이 있으면 빨간 점, 노트북 사이드바 알림 항목에는 강조를 표시한다.
알림 목록에 방문하여 확인하면 미확인 표시를 해제한다. 숫자 배지는 추가하지 않는다.
목록은 뒤로가기·`알림` 제목·최근 알림 영역으로 구성한다. 알림 문구와 상대 시각을 두 줄, 최신순으로 표시한다.
예: 오늘 오전 8:12 / 어제 오후 3:40 / 3일 전. 개인정보를 로그용 메시지로 복제하지 않는다.
빈 상태 `아직 알림이 없어요`, 실패는 공통 오류/재시도다. 클릭 이동 규칙은 필요한 범위에서 담당자가 결정한다.
출석 알림은 출석 데이터 폐기 정책을 따른다. 다른 알림·봉사·공지 보관 기간은 운영 담당 결정 항목이다.

근거: SRC-USER-UI `알림 진입점`, `알림 유형`, `알림 화면 구성`와 이후 삭제 결정, SRC-COMMUNITY.
