# 봉사·공지·알림

### REQ-COM-001 — 봉사 관리 명단

봉사는 기숙사에서 잘못했을 때 받는 벌칙이다. 사감·기숙사 자치위원(관리자)이 봉사 관리 명단에서 학생의 봉사 횟수를 관리한다(DEC-021).
명단은 서비스에 저장된 전체 학생이다. 명단에 학생을 따로 추가·제외하는 단계는 없다. 학생은 관리 API를 사용할 수 없다.
각 행은 이름·학번·호실·최근 활동·봉사 횟수와 `−`/`+`, 당일 봉사자 버튼을 표시한다. 목록은 호실순(호실 → 이름 → 학번)이며 웹은 같은 호실끼리 묶어 보여준다.
검색어 하나로 호실·학번·이름을 찾는다. 숫자는 호실 번호나 학번이 정확히 같은 학생만 찾고(`412` → 412호), 그 밖에는 이름에 포함 → 초성 일치(`ㄱㅁㅇ`) → 자음·모음 오타 1개 순으로 앞에 둔다.
층(호실 맨 앞자리, 412호 → 4층)으로 거를 수 있고, 봉사가 남은 학생만·오늘 당일 봉사자만 보기로 거를 수 있다.

근거: SRC-VOLUNTEER-PENALTY. 이전의 명단 추가·제외(SRC-ADMIN-UI, SRC-COMMUNITY, DEC-010)는 이 결정으로 대체됐다.

### REQ-COM-002 — 봉사 횟수 조정

봉사 횟수는 학생이 **앞으로 해야 할 봉사 횟수**다. 학생이 잘못하면 관리자가 `+`로 늘린다(DEC-020).
봉사를 마친 것은 당일 봉사 완료(REQ-COM-006)로 1 줄이고, 사감이 특별한 사정으로 감면할 때는 `−`로 줄인다(DEC-021).
관리자 목록에 이름 / 최근 활동 / 봉사 횟수를 표시한다. 최근 활동 없으면 `-`, 횟수는 `0회`다.
각 학생의 횟수 배지 옆 `+`와 `−` 버튼으로 1회씩 즉시 가감한다. 확인 단계나 활동명 입력은 없다. 횟수가 0이면 `−`는 비활성화하며 0 미만이 되지 않게 서버도 검증한다.
각 조정 날짜를 기록하고 활동명은 비운다. 최근 활동에는 날짜만 표시한다.
통신 재시도는 같은 조정을 중복 반영하지 않지만 사용자가 새로 누른 별도 클릭은 한 번 더 반영한다.
`+`의 성공/실패 문구는 `봉사 1회를 추가했습니다.` / `봉사 추가에 실패했습니다. 다시 시도해 주세요.`, `−`는 `봉사 1회를 차감했습니다.` / `봉사 차감에 실패했습니다. 다시 시도해 주세요.`를 사용한다.
전체 평균·총계 통계와 학생 이름 클릭 상세는 추가하지 않는다. 횟수 조정은 알림을 만들지 않는다. 봉사 알림은 당일 봉사자 지정(REQ-COM-006)에만 연결한다.

근거: SRC-NOTION-CHECKUPZIP의 사용자 승인 항목 `봉사 횟수 가감`, 횟수의 의미와 알림 시점은 SRC-VOLUNTEER-DUTY, 감면 용도는 SRC-VOLUNTEER-PENALTY.

### REQ-COM-003 — 학생 봉사 조회

학생은 본인의 남은 봉사 횟수만 확인한다. 다른 학생 조회나 수정은 불가하다.
최신 사용자 확정의 `학생은 자기 봉사 횟수만 확인`이 과거 첨부의 활동별 내역 목록보다 우선한다.
봉사 횟수는 일일 출석 초기화 때 지우지 않는다.

근거: SRC-COMMUNITY, SRC-HANDOFF, SRC-VOLUNTEER-DUTY.

### REQ-COM-004 — 공지

사감·자치위원 모두 공지를 작성·수정·삭제할 수 있다. 학생은 공지 목록을 읽기만 한다.
공지 제목/내용·작성/수정 시각과 목록 표시는 웹/백엔드가 설계한다. 댓글·첨부·상단 고정·예약 발행은 추가하지 않는다.
새 공지 등록 알림은 `기숙사 공지 알림 수신`을 선택한 학생에게만 생성한다.
알림 미동의 학생도 공지 목록은 볼 수 있다. 선택 동의를 공지 열람 권한과 혼동하지 않는다.
공지 수정/삭제 때 별도 새 알림을 발송하는 기능은 정의되지 않았다.

근거: SRC-COMMUNITY의 사용자 직접 결정.

### REQ-COM-005 — 웹 내부 알림

남기는 유형은 출석 완료, 당일 봉사자 지정, 기숙사 공지사항 등록 3개다.
얼굴 재등록 요청과 QR 만료 임박은 명시적으로 삭제됐다. 새로운 알림 유형을 만들지 않는다.
출석 완료 알림은 상태가 실제 성공 처리될 때 생성한다. 중복 인증은 중복 발송하지 않는다.
봉사 알림은 당일 봉사자로 지정될 때 생성한다. 횟수 조정과 봉사 완료는 알림을 만들지 않는다. 지정을 취소하면 그 지정 알림을 지운다(DEC-020).
공지 알림만 선택 동의에 연결한다. 서비스 범위는 웹 내부 알림이며 푸시는 포함하지 않는다.
모바일 홈 헤더 벨에 읽지 않은 알림이 있으면 빨간 점, 노트북 사이드바 알림 항목에는 강조를 표시한다.
알림 목록에 방문하여 확인하면 미확인 표시를 해제한다. 숫자 배지는 추가하지 않는다.
목록은 뒤로가기·`알림` 제목·최근 알림 영역으로 구성한다. 알림 문구와 상대 시각을 두 줄, 최신순으로 표시한다.
예: 오늘 오전 8:12 / 어제 오후 3:40 / 3일 전. 개인정보를 로그용 메시지로 복제하지 않는다.
빈 상태 `아직 알림이 없어요`, 실패는 공통 오류/재시도다. 클릭 이동 규칙은 필요한 범위에서 담당자가 결정한다.
출석 알림은 출석 데이터 폐기 정책을 따른다. 다른 알림·봉사·공지 보관 기간은 운영 담당 결정 항목이다.

근거: SRC-USER-UI `알림 진입점`, `알림 유형`, `알림 화면 구성`와 이후 삭제 결정, SRC-COMMUNITY, 봉사 알림 시점은 SRC-VOLUNTEER-DUTY.

### REQ-COM-006 — 당일 봉사자 지정·완료

사감(관리자)은 매일 그날 봉사할 학생을 봉사 관리 명단에서 지정한다. 인원은 고정하지 않고 관리자가 정한다.
지정할 수 있는 학생은 봉사 횟수가 1 이상인 학생이다. 0인 학생을 지정하면 `봉사가 없습니다.`를 표시하고 서버도 거부한다(DEC-021).
지정 단위는 학생·운영일이다(DEC-006). 같은 학생을 같은 운영일에 두 번 지정하지 않는다.
지정되면 그 학생에게 봉사 알림을 만든다. 관리자는 지정을 취소할 수 있고, 취소하면 그 지정의 알림을 지운다. 취소 알림은 따로 만들지 않는다.
봉사를 마치면 기숙사 자치위원이 같은 행의 `완료`를 누른다. 완료는 그 지정을 완료로 표시하고 봉사 횟수를 1 줄이며, 한 번만 반영된다. 완료한 지정은 취소할 수 없다.
지정·취소는 봉사 횟수를 바꾸지 않는다. 학생은 지정·완료 API를 사용할 수 없다.
지정·완료 버튼은 봉사 관리 명단 행에 함께 있다. 행은 오늘 지정 상태(없음/지정됨/완료됨)에 따라 버튼을 바꾼다.

| 결과 | 문구 |
| --- | --- |
| 봉사 없는 학생 지정 | 봉사가 없습니다. |
| 이미 지정됨 | 이미 오늘 봉사자로 지정된 학생입니다. |
| 이미 완료됨 | 이미 봉사를 완료했습니다. |

근거: SRC-VOLUNTEER-DUTY, 지정 대상·완료 차감·화면 위치는 SRC-VOLUNTEER-PENALTY.
