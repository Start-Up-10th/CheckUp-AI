# 제품 명세 목차

기준: 인터뷰를 처음부터 다시 시작한 이후의 최신 사용자 결정, 최신 제공 화면 명세, 최종 통합 요약.
초기 인터뷰의 지각 신청·시간표·수동 학생 명단 등록 정책은 복구하지 않는다.

| 분야 | 명세 | 주요 내용 |
| --- | --- | --- |
| 범위 | [scope.md](scope.md) | 목표·스택·제외 기능 |
| 인증 | [identity.md](identity.md) | DataGSM·권한·동의·프로필 |
| 얼굴 | [face.md](face.md) | 등록·벡터·다수 인식·화면·오프라인 |
| 출석·QR | [attendance.md](attendance.md) | 세션·중복·갱신·수동 수정·08시 |

| 공지·봉사 | [community.md](community.md) | 봉사 관리·공지·알림 |

`### REQ-분야-번호`가 추적 가능한 요구사항 정의다. 각 REQ는 [수용 시나리오](../../tests/acceptance/scenarios.json)에 연결된다.
시나리오는 구현 기준이며 현재 실행한 제품 테스트가 아니다. 상태는 `specified`에서 시작한다.

## 사실과 구현 판단

- 사용자·첨부 문서 근거는 [출처 지도](../sources/README.md)에 기록한다.
- 기존 통합 요약에만 있는 정책도 버리지 않고 해당 항목에 출처를 표시한다.
- 기술적으로 아직 검증되지 않은 부분은 [기술 결정](../decisions.md)에 남긴다.
- UI에 별도 예외 문구가 정의되지 않았다는 것은 서버 검증을 생략하라는 의미가 아니다.
- 문서에 없는 운영 비밀값, 전체 학생 조회 API, 졸업 이벤트 API를 존재한다고 가정하지 않는다.
