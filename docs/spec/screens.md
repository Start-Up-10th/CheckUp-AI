# 화면·표시·반응형

### REQ-UI-001 — 관리자 홈 전개도

최신 관리자 홈 이미지가 기준이다. 좌측 서비스 명칭은 `ADMIN / 기숙사 출석 관리`다.
홈 상단에 선택된 층의 `3층 전개도` 같은 제목, 우측에 3·4·5층 탭을 둔다.
상단 출석/미출석 2개 통계 카드는 선택한 층의 학생 수를 집계한다. 총원 통계 카드는 추가하지 않는다.
호실은 DataGSM 정보로 자동 그룹화하고 방 번호 오름차순으로 배열한다.
넓은 화면은 제공 이미지의 7열 그리드 느낌을 따르고 좁은 화면에서는 반응형으로 줄인다.
카드 좌상단은 호실, 하단은 `출석 인원 / 해당 호실 배정 인원`이다. 분모를 4명으로 고정하지 않는다.
전원 출석은 라임 계열, 일부 미출석은 회색 계열로 구분한다.
빈 방은 없다는 사용자 전제에 따라 공실 범례·공실 관리·빈 방용 다이얼로그는 구현하지 않는다.
호실 추가/제거·배치 편집 기능은 없다. 방 카드에서 상세를 연다.

근거: SRC-HOME-IMAGE, SRC-INTERVIEW `빈 방이 없어`, SRC-ADMIN-UI 중 최신 결정과 일치하는 항목.

### REQ-UI-002 — 호실 상세

방 번호와 배정 학생 수/출석 학생 수, 학생 행, `닫기`/`저장`을 표시한다.
학생은 이름순이다. 동명이인은 학번으로 안정 정렬하는 구현 기본값을 사용한다.
`1번`, `2번`은 표시 순번이며 침대 번호가 아니다. 호실 정원/침대 DB를 만들지 않는다.
각 행에 이름, 출석/미출석 선택을 표시한다. `4인실` 대신 실제 배정 인원 기준으로 표현한다.
관리자는 편집 가능하고 학생에게 보여주는 해당 정보는 읽기 전용이다.
수동 수정 동작은 REQ-ATT-006을 따른다.

근거: SRC-ROOM-IMAGE, SRC-INTERVIEW.

### REQ-UI-003 — 학생 홈

학생 홈은 본인 호실 카드가 기본이다. 이름·학번과 `기숙사 N층` 제목을 표시한다.
본인 호실 학생 이름과 현재 출석/미출석 상태를 이름순으로 읽기 전용 표시한다.
초기 인터뷰의 학생 전체 층 전개도 대신 최신 학생 화면 명세의 본인 호실 범위를 적용한다.
과거 침대 2×2·창문·출입문·침대 1~4번 표시는 최신 호실 목록 방식으로 대체한다.
QR 카메라 진입, 홈/마이 이동, 알림 진입점을 제공한다.
본인 미등록이면 얼굴 등록으로 이동한다. 서버 실패: `서버와 연결이 원활하지 않습니다.`

근거: SRC-USER-UI `메인 화면 진입`, `내 호실 현황`, SRC-ROOM-IMAGE, SRC-INTERVIEW.

### REQ-UI-004 — 학생 마이페이지와 내비게이션

이름 아래 `학번 · 기숙사 N층 NNN호`를 표시한다. 봉사 횟수로 이동하는 `봉사 활동` 항목과 로그아웃이 있다.
출석 과거 기록 메뉴는 없다. 프로필 사진은 미설정 상태에서 시작한다.
모바일 홈/마이 2개 하단 탭은 현재 화면을 강조한다.
QR 카메라·봉사·알림 화면은 뒤로가기 + 제목을 표시하며 모바일 하단 탭을 숨긴다.
학생 노트북 화면은 프로필·홈·QR 출석·마이페이지·알림·하단 로그아웃의 좌측 사이드바를 사용한다.
원문 넓은 화면 기준은 1440×900, 사이드바 240px다. 고정 크기로 작은 화면을 깨뜨리지 않는다.
공지 목록 접근은 새 확정 기능이므로 웹 담당자가 기존 내비게이션 안에서 자연스럽게 연결한다.

근거: SRC-USER-UI, SRC-COMMUNITY.

### REQ-UI-005 — 관리자 반응형

컴퓨터는 라벨 있는 좌측 고정 사이드바, 패드는 축소 레일, 휴대폰은 하단 4개 탭을 사용한다.
기본 메뉴는 홈 / QR 코드 생성 / 얼굴 인식 생성 / 봉사자 관리다. 휴대폰 단축 라벨은 홈 / QR / 얼굴 / 봉사다.
원문 사이드바 폭 300px를 기준으로 이미지 비례와 반응형을 조정한다.
로그인·전개도·호실 수정·QR·카메라·카메라 전체화면·봉사 관리/추가를 세 화면 크기에서 제공한다.
전체화면 버튼과 LIVE는 카메라 영역에 있다. QR 전체화면을 추가하지 않는다.
공지 작성/관리 진입과 휴대폰 로그아웃 위치는 웹 담당자가 접근 가능하도록 추가하며 공지 CRUD 권한은 유지한다.

근거: SRC-ADMIN-UI, SRC-CAMERA-IMAGES, SRC-HOME-IMAGE. 공지는 SRC-COMMUNITY의 추가 요구.

### REQ-UI-006 — 공통 상태와 문구

목록 로딩은 본문 스켈레톤으로 표시하고 헤더/내비게이션은 유지한다.
빈 목록은 `아직 데이터가 없어요`, 오류는 `불러오지 못했어요` + 다시 시도,
비로그인은 `로그인이 필요해요` + 로그인하기를 표시한다. 알림 빈 상태는 `아직 알림이 없어요`다.
상태 메시지는 가로 배너, 성공 체크 아이콘, 오류/안내 점 아이콘을 사용한다.
일시 표시 시간·카메라 미권한 전용 화면처럼 미정의인 상세는 담당자가 일관된 기본 상태로 처리한다.
특정 예외 메시지가 원문에 없다고 예외 검증 자체를 없애지 않는다.

| 상황 | 제공 문구 |
| --- | --- |
| 학생 로그인 실패 | 로그인에 실패했습니다. 다시 시도해 주세요. |
| 로그인 성공 | 로그인되었습니다. |
| 관리자 인증 실패 | 계정 또는 비밀번호가 올바르지 않습니다. |
| 관리자 권한 부족 | 관리자 권한이 없는 계정입니다. |
| 내 정보 조회 실패 | 정보를 불러오지 못했습니다. |
| 전개도 조회 실패 | 전개도를 불러오지 못했습니다. |
| 전개도 수정 실패 | 전개도 변경에 실패했습니다. 다시 시도해 주세요. |
| 학생 검색 결과 없음 | 검색 결과가 없습니다. |
| 학생 목록 조회 실패 | 학생 목록을 불러오지 못했습니다. 다시 시도해 주세요. |
| 봉사 조회 실패 | 봉사 활동 내역을 불러오지 못했습니다. |

얼굴·QR·봉사 변경 문구는 해당 분야 명세에서 관리한다. 문구에 자체 비밀번호가 언급되더라도 자체 로그인 폼을 추가하지 않는다.

근거: SRC-USER-UI, SRC-ADMIN-UI.
