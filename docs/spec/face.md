# 얼굴 등록·인식

### REQ-FACE-001 — 휴대폰 최초 등록

동의 후 휴대폰에서 얼굴 촬영 창을 표시한다. 얼굴 방향을 돌리도록 안내하며 영상을 촬영한다.
약 100개 프레임을 추출하여 얼굴 유무·선명도·조명·방향 품질을 평가한다.
카메라 프리뷰의 코너 가이드와 `얼굴을 화면 안에 맞춰 주세요` 안내를 제공한다.
최초 등록 과정에서 `초기화`로 미저장 촬영본을 폐기하고 재촬영할 수 있다.
`저장`은 검증된 대표 벡터를 등록하고 학생 홈으로 이동한다. 이미 등록된 얼굴을 다시 바꾸는 기능은 없다.
노트북에서는 카메라를 열지 않고 아래 안내만 표시한다.

```text
얼굴 등록은 휴대폰에서만 가능해요
휴대폰으로 DataGSM 로그인 후 얼굴을 등록해 주세요.
```

미검출: `얼굴 인식에 실패했습니다. 다시 촬영해 주세요.`
저조도: `조명이 어두워요. 밝은 곳에서 촬영해 주세요.`
프레임 목표 수를 맞추려고 저품질·다른 사람·중복 프레임을 무조건 채우지 않는다.

근거: SRC-INTERVIEW, SRC-USER-UI의 `얼굴 촬영`, `초기화 버튼`, `저장 버튼`.

### REQ-FACE-002 — 대표 벡터와 원본 폐기

학생별 대표 얼굴 벡터 약 20개를 저장한다. 단일 평균 벡터 하나로 축소하지 않는다.
대표 선택·정규화·거리 함수·차원·모델 버전은 AI 담당자가 검증하여 계약에 기록한다.
영상·추출 프레임은 인식/특징 추출에만 일시 사용하고 즉시 폐기한다. DB·객체 저장소·백업·로그에 영속 저장하지 않는다.
등록 실패·취소·네트워크 오류에서도 임시 원본을 정리한다. 장기 학습 데이터셋을 만들지 않는다.
MediaPipe 검출/랜드마크만으로 신원 임베딩이 구현됐다고 보고하지 않는다. 추가 모델 선정은 DEC-003의 개발 과제다.
원문 `학생별 특징 사전 학습`은 이 프로젝트에서는 등록 벡터와 대조하는 의미이며 학생마다 모델을 재학습하라는 요구가 아니다.

근거: SRC-INTERVIEW의 `대표 벡터 20개`, `원본 즉시 삭제`; SRC-QR-FACE. 기술 범위는 SRC-MEDIAPIPE.

### REQ-FACE-003 — 벡터 수명

얼굴 벡터는 졸업할 때까지 보관한다. 3학년이라는 이유만으로 즉시 삭제하지 않고 실제 졸업 시점에 삭제한다.
전학·기숙사 퇴사 학생은 해당 대상임을 확인한 뒤 벡터를 삭제한다. 재학생 여부와 기숙사 재실 자격은 같은 개념으로 가정하지 않는다.
DB뿐 아니라 캐시·기기 사본·백업 복구 경로에도 삭제가 적용돼야 한다.
졸업일·전학/퇴사 신호·조회 주기는 DataGSM 실연동 때 확인한다. 존재하지 않는 필드를 작성하지 않는다.
네트워크 실패나 일시적 조회 누락만으로 학생을 탈퇴 처리하지 않는다.

근거: SRC-INTERVIEW, SRC-HANDOFF. 제공 신호 확인은 DEC-002.

### REQ-FACE-004 — 관리자 카메라 세션

관리자가 웹 메뉴 `얼굴 인식 생성`을 열면 선택한 용도(기본 기숙사)의 내장 카메라가 자동 실행된다.
시작 버튼은 없다. 페이지를 벗어나면 카메라·프레임 전송·관련 인증 세션이 종료된다.
목적 탭 변경은 기존 처리와 분리하여 새 목적에 적용한다. 다른 기기의 세션은 종료하지 않는다.
브라우저 최초 권한 요청은 필요할 수 있다. 권한을 우회하거나 허용 전 LIVE를 표시하지 않는다.
실행 실패 문구: `카메라를 자동으로 실행하지 못했습니다.`
관리자는 페이지에 진입한 뒤 필요할 때 전체화면 버튼을 누른다. 기기 부팅 시 전체화면으로 자동 시작하지 않는다.

근거: SRC-QR-FACE, SRC-CAMERA-IMAGES, SRC-INTERVIEW.

### REQ-FACE-005 — 다수 얼굴과 중복

한 화면에서 여러 얼굴을 동시에 검출·인식한다. 각 얼굴별로 대표 벡터와 대조한다.
학생은 지나가며 인식하고 실패하면 현장 관리자가 재시도 또는 QR을 안내한다.
불확실하면 실패로 처리하며 가장 비슷한 학생에게 무조건 출석을 부여하지 않는다.
여러 얼굴 중 한 명 성공·다른 한 명 실패가 각각 처리돼야 한다. 서로의 이름·실패 횟수를 섞지 않는다.
중복 성공은 성공 안내만 하며 출석·완료 알림을 중복 생성하지 않는다.
실패 얼굴의 신원을 모르는데 이름/학번을 붙이지 않는다. 실패 기록은 인식 실패로 남기고 특정 학생의 미출석 사유로 임의 연결하지 않는다.
실패 자체는 이미 출석한 학생의 상태를 미출석으로 바꾸지 않는다. 라이브니스는 MVP 범위 밖이다.

근거: SRC-INTERVIEW의 `다수 인식 가능`, `인식 실패`, SRC-QR-FACE.

### REQ-FACE-006 — 결과·실패 안내

카메라 하단에 성공 또는 실패를 잠시 표시한다. 성공이면 목적에 맞게 자습실 출석/기숙사 입소를 처리한다.
문구 `인식 실패 · 3회 초과 시 QR로 출석`을 유지한다.
최신 상세 문구의 `3회 초과`는 4번째 연속 실패부터 안내하는 것으로 해석한다(DEC-004).
매 영상 프레임을 실패 1회로 세지 않는다. 익명 얼굴 트랙별 인식 시도 단위를 사용하고 성공·화면 이탈 시 연속 횟수를 정리한다.
다수 얼굴에서 누구를 실패자로 셀지 추정하지 않도록 트래킹 정책은 AI/웹 담당자가 검증한다.

근거: SRC-QR-FACE. 경계값·시도 단위는 문구 모호성을 해소하는 구현 기본값 DEC-004.

### REQ-FACE-007 — LIVE·전체화면·최근 목록

카메라 패널에 `카메라 화면` 라벨, 정상 작동 중 점 아이콘 + LIVE, 우상단 전체화면 버튼을 둔다.
전체화면은 카메라 세션의 표시 모드다. 전체화면에 들어가거나 닫는 것으로 새 인식 세션을 만들거나 기존 세션을 종료하지 않는다.
좌상단 닫기로 일반 화면에 복귀한다. 대기 문구는 `인식 대기 중`, 보조 문구는 `가이드 안에 얼굴을 맞춰 주세요`다.
성공 시 `성공 · 학번 이름`으로 교체한다. 다수 결과의 표시는 담당자가 일관되게 설계한다.
최근 인식은 데스크톱 우측, 좁은 화면 아래에 최신순으로 표시한다.
성공 행은 `학번 이름 / 인식 시각 · 성공`, 실패는 신원 없는 `인식 실패 / 인식 시각 · 실패`로 표현한다.
성공 초록·실패 빨강을 사용하되 텍스트도 함께 제공한다. 기록 없으면 공통 빈 상태를 표시한다.
최근 목록은 장기 이력이 아니며 당일 임시 기록이다.

근거: SRC-QR-FACE, SRC-CAMERA-IMAGES. 미식별 이름 표기는 구현 기준.

### REQ-FACE-008 — 오프라인 인식과 임시 기록

직전 통합 명세에 포함된 요구: 출입구 기기가 서버 연결 중단 중에도 캐시된 벡터로 인식하고,
결과를 임시 보관한 뒤 연결 복구 시 동기화한다. 여러 출입구의 중복은 가장 이른 기록만 인정한다.
당일 임시 기록은 다음 날 08:00 초기화 경계를 넘어 보관하지 않는다. 폐기된 운영일 기록을 늦게 업로드해 출석을 되살리지 않는다.
QR 인증은 서버 연결이 필요하다.
이 요구는 웹에서 실제 임베딩 모델·인증된 벡터 캐시·기기 시계 오차까지 검증해야 한다.
FastAPI만 두면 브라우저 오프라인 인식이 된다고 가정하지 않는다. 구현 근거와 배포 가능성을 DEC-005에 기록한다.
학생 브라우저로 전체 얼굴 벡터를 배포하는 방식은 사용하지 않는다. 관리자 기기의 캐시도 로그아웃·삭제 대상 반영 시 정리한다.

근거: SRC-HANDOFF. 실행 가능성은 아직 실측하지 않았다.
