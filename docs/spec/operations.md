# 인프라·배포·데이터 수명

### REQ-OPS-001 — GSM SV

학교 제공 GSM SV IaaS의 Ubuntu 22.04 LTS VM을 사용한다.

| 도메인 | 용도 |
| --- | --- |
| `gsmsv.site` | 콘솔 |
| `ssh.gsmsv.site` | SSH 접속 |
| `service.gsmsv.site` | VM 웹 서비스 HTTP/SVC 접속 |

USER는 최대 3개 VM, 30일 뒤 자동 삭제된다. PROJECT_OWNER는 제공 문서상 VM 한도·만료 제한이 없다.
운영용은 자동 삭제되지 않는 프로젝트용 VM을 확보한다. 실제 계정 권한이 확보됐다고 단정하지 않는다.
VM 생성 시 SSH/HTTP/SVC 포트가 자동 할당된다. 정확한 URL·포트·TLS 지원은 발급 후 확인한다.
상위 도메인만 보고 운영 HTTPS 주소나 인증서를 발급받았다고 가정하지 않는다.
VM 방화벽·전원 제어·CPU/RAM 모니터링은 플랫폼 기능이다.
초기 비밀번호를 교체하거나 SSH Key를 구성한다. VM 사양과 GPU 배정 여부는 데브옵스가 확인한다.

근거: SRC-GSMSV, SRC-HANDOFF.

### REQ-OPS-002 — 배포와 비밀값

Docker와 GitHub Actions로 배포한다. Compose를 초기 실행 구성으로 삼되 구성 상세는 데브옵스가 관리한다.
GitHub 이미지 레지스트리·브랜치 트리거·테스트 순서·롤백·리버스 프록시·포트는 개발팀이 결정한다.
실제 서버 주소와 OAuth 운영 Redirect URI는 배포 준비 시 채운다.
Client Secret은 Spring 백엔드의 서버 `.env`/런타임 secret으로만 주입하며 프론트 번들에 포함하지 않는다.
SSH 키 등 CI 비밀은 GitHub Secrets, 운영 DB/Redis 자격증명은 서버의 비공개 환경 값으로 관리한다.
Git에는 값 없는 `.env.example`만 둔다. 비밀값을 사용자에게 채팅으로 보내 달라고 요청하지 않는다.
운영 카메라 접근에 필요한 HTTPS를 확인한다. 실제 운영 배포는 하네스 생성만으로 수행하지 않는다.

근거: SRC-STACK, SRC-DATAGSM, SRC-HANDOFF. 기술 위임은 SRC-INTERVIEW.

### REQ-OPS-003 — 영속화와 백업

학생 정보·설정·얼굴 벡터·유지해야 하는 공지/봉사 데이터는 서비스 재시작 후 남아야 한다.
PostgreSQL은 영속 볼륨을 사용한다. Redis의 일시 상태와 영속 데이터 역할을 분리한다.
이전 통합안: 얼굴 벡터와 학생 설정을 매일 암호화 백업하며 당일 출석/인식 임시 기록은 백업하지 않는다.
백업 위치·기간·암호화 키 관리·복구 방식은 데브옵스가 결정한다. 같은 VM 볼륨만으로 VM 삭제 복구가 가능하다고 설명하지 않는다.
일반 DB 전체 덤프가 당일 기록을 섞어 보관하지 않도록 백업 대상을 명시한다.
공지/봉사 데이터의 백업 포함 여부와 보존기간도 운영 담당자가 정의하고 문서화한다.
졸업/전학/퇴사 삭제가 복구 후 되살아나지 않도록 백업 삭제 또는 대상별 복원 제외·키 폐기 방식을 검증한다.

근거: SRC-HANDOFF, SRC-INTERVIEW의 백업 위임.

### REQ-OPS-004 — 수명별 정리

| 데이터 | 기준 |
| --- | --- |
| 얼굴 원본 영상·프레임 | 특징 추출에만 임시 사용, 완료/실패/취소 후 즉시 폐기 |
| 대표 얼굴 벡터 약 20개 | 졸업까지; 확인된 전학/퇴사 시 삭제 |
| 당일 출석·최근 인식·수동 수정 상태·기기 임시 기록 | 다음 날 Asia/Seoul 08:00 정리 |
| QR 활성 세션/토큰 | 페이지 종료·만료에 맞춰 정리; 발급 이력 없음 |
| 학생 정보·동의·프로필·봉사 누적·공지 | 당일 초기화 대상 아님; 목적별 운영 보관정책 적용 |
| 출석 알림 | 과거 출입 기록의 우회 저장을 막기 위해 동일 운영일 정리 |

서버 정리 작업은 반복 실행해도 안전해야 한다. DB·캐시·기기·백업을 포함해 삭제 검증을 수행한다.
보관기간과 학교 동의 전문의 최종 문안은 운영 자료이며 개발 시작을 막는 재인터뷰 항목으로 취급하지 않는다.
실제 사용자 운영 전에는 담당자가 문안·삭제 실행·복구 경로를 확인한다.

근거: SRC-INTERVIEW, SRC-USER-UI의 동의 문안 임시 표시, SRC-HANDOFF; 출석 알림은 DEC-009.
