# 인터뷰 핵심 사용자 결정 발췌

현재 대화에서 직접 확인되는 문장을 주제별로 발췌했다. 전체 transcript가 아니며 원래 순번만 있는 답변의 의미는 새로 붙이지 않았다.

| 주제 | 사용자 발언 |
| --- | --- |
| 인터뷰 재시작 | 지금까지 했던 거 전부 삭제하고 처음부터 다시 질문 하자 |
| 관리 권한 | 사감 자치위원 둘다 같은 권한을 가져야함 |
| 규모 | 출입구 3개 200명 정도 |
| 등록 | 최초 등록은 회원가입 이후에 바로 등록 창을 띄우게 해서 얼굴을 돌리라고 하면서 사진 100개 정도 DB에 등록 해놓을거임 |
| 원본 처리 정정 | 얼굴 사진은 바로 삭제하고 얼굴 사진에서 나온 벡터 값만 DB에 저장해놓을거임 |
| OAuth | 우리 학교 전용 OAuth가 있음 거기서 가져올거 |
| 대상 | 전체가 다 기숙사생임 |
| 관리자 | OAuth에 자치위원 명단과 사감 계정이 따로 다 있음 |
| QR 방식 | QR은 관리자가 QR 만들어서 학생들이 QR 일반카메라로 찍어서 웹사이트 들어가면 출석 처리되게 하려고 |
| QR 교체 | 15분마다 |
| 통과 인식 | 걍 지나가면서 인식하게 하면 좋을 거 같은데 인식 안되면 자치위원이 다시 오라해서 인식하게 하면 되니까 |
| 데이터 수명 | OAuth에 무슨 학년인지 다 있거든 3학년이면 졸업후에 다 삭제 하는 걸로 하자 |
| 일일 기록 | 당일만 저장 ㄱ / 다음날 오전 8시에 초기화 하자 |
| 최종 확정 제거 | 확정하는 거 자체를 없애자 언제든 관리자가 켜서 인식되면 바뀌게 |
| 서버 | 학교 내부 서버 |
| 프로필 | 프로필 사진은 일단 비워두고 나중에 하고 싶은 걸로 채우게 하는 걸로 바꾸는 걸로 바뀜 |
| 시간대 제거 | 그냥 키면 인식하고 끄면 인식 안하게 하는 걸로 바뀜 |
| 얼굴 동의 | 얼굴정보 동의 필수로 하자 |
| QR 이력 | 생성이력 빼는걸로 함 |
| 다수 얼굴 | 다수 인식 가능으로 바꾸자 |
| 페이지 수명 | QR·카메라 페이지 진입 시 자동 시작, 이탈 시 종료로 하자 |
| 호실 | DataGSM에 호실 번호 제공함 침대 번호는 필요 없음 |
| 등록 정정 | 얼굴 등록 데이터는 동영상으로 찍어서 사진 100개 정도 뽑고 대푯값 저장해놓기로함 |
| 여러 출입구 | 여러곳 인식 되면 가장 이른 기록만 인정하게 하자 |
| QR·벡터 | QR 기록 필요 없음 층 나누지 마 공용 QR / 이름 순으로 정렬 대표 벡터 20개 정도로 저장하자 |
| 장치 | 출입구별 기기 1대임 / 내장 카메라로 하자 |
| 현장·웹 | 관리자가 무조건 앞에 있을거니까 신경 안써도 됨 / 얼굴 재등록은 그냥 하지 말자 / 임시 기록 보관은 당일 끝나면 폐기 / 그리고 우리는 웹임 |
| 독립 QR | 관리자가 페이지 클릭할때마다 다 다른 QR이 생성되게 바꿔 |
| 수동 출석 | 관리자 수동 출석 수정은 그냥 버튼으로 해서 출석 누르면 출석 되게 하면 되잖아 |
| 배정 수 | DataGSM에 사람마다 무슨 호실인지 있으니까 그걸로 채우면 되는 거아니냐? |
| 벡터 보존 | 얼굴 벡터는 졸업 할때까지 계속 보관하고 전학 퇴사 학생은 너 말대로 ㄱ |
| 삭제 알림 | 얼굴 재등록은 그냥 지워 QR 만료 임박 알림도 지워 |
| 유지 동의 | 개인정보 동의의 기숙사 공지 알림 수신 선택 항목 이건 남기자 |
| 배포 | 데브옵스: Docker, GitHub Actions 이거로 배포함 |
| 기술 위임 | 나머지 다 백엔드랑 데브옵스가 알아서 하게 하면 되는 거 아니냐 |
| 봉사 | 관리자가 봉사 학생을 추가/제거하고, 학생은 자기 봉사 횟수만 확인. 이거 맞음 |
| 공지 | 관리자가 공지 작성 수정 삭제 가능하고 학생은 공지 목록만 봄 공지 알람 수신 선택 항목과 연결해 |
| 홈 | 홈 화면은 이미지 처럼 하면 됨 |
| 공실 | 빈 방이 없어 그건 걱정 안해도 됨 |

앞 문장을 뒤 문장이 수정한 경우 최종 명세는 뒤 결정을 따른다. `등록 사진 100개 DB 저장`은 원본 폐기·20벡터 결정으로 대체됐다.
